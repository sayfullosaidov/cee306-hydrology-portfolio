1. The Scope of Machine Learning¶

This section is just to quickly give you an idea of how the things you will do in this notebook fit into the machine learning landscape. Broadly: we are planning to use a convolutional neural network (CNN) - but what does that mean, and where does that fit into the scope of machine learning?

Everything in this notebook is a subset of artificial intelligence (AI), any system or technique that perceives its environment and mimics human intelligence by taking logical actions. Examples include industrial robotics or virtual assistants such as Google Home, Alexa, Siri, etc.

Machine learning (ML) is thus a subset of AI, with the added constraint that the program must learn (in the evaluation sense) patterns from the input data. ML products are trained, evaluated on performance, and then can make predictions on new data based on its training.

One rapidly growing subset of machine learning is deep learning (DL). Inspired by the information processing patterns that the human brain performs, DL algorithms attempt to identify patterns in the data through a series of layers by labelling, assigning, and categorizing the data. One main indicator of a DL algorithm is its ability to extract relevant features from the data, without explicitly being told that said features are important.

Keeping with the brain analogy, there are many types of neural networks used in DL. The one we will be using in this notebook is called a convolutional neural network (CNN), a type of neural network that does well in video/image processing and time series analyses. One major advantage of CNNs is that pre-processing is kept at a minimum - the algorithm will optimize filters in its learning process.

2. Snow Data¶

A machine learning algorithm is only as good as the data provided to it. Great care must be taken in retrieving, sorting, and cleaning data before it even touches a ML/DL algorithm. This section will use python libraries to retrieve and clean up data from SNOTEL sites.

Once the data is cleaned, it must be partitioned for the model. The bulk of the data will be used to initially fit the model; this is called the training dataset. Once the model is fit, a validation dataset (completely separate from the training dataset) is usually used to provide an unbiased evaluation of a model. It is at this stage that hyperparameters (parameters that control the DL algorithm's learning process) will be tuned. Finally, a test dataset is used to provide a final evaluation of the model.

In this notebook, we will be skipping the validation step, and go right to final model evaluation from training.

We can streamline this process even more. Say you have three variables, one each for the start date, end date, and station ID. We can combine all the steps above into a single function, so all it takes is one function call in one line to get a pandas dataframe of the data.

In [6]:
# define a function to get SWE based on the client, begin and end date, and station triplets
def get_snotel_swe(client, user_stationTriplets, user_beginDate, user_endDate):

    # get the data using zeep and the arguements given above
    instant_data_WTEQ = client.service.getData(duration='DAILY', stationTriplets=user_stationTriplets,
                                          elementCd='WTEQ', ordinal=1, beginDate=user_beginDate,
                                          endDate=user_endDate, getFlags = True)

    # we can also do the same for 'TAVG', the average temperature
    instant_data_TAVG = client.service.getData(duration='DAILY', stationTriplets=user_stationTriplets,
                                          elementCd='TAVG', ordinal=1, beginDate=user_beginDate,
                                          endDate=user_endDate, getFlags = True)

    # as well as 'PRCP', precipitation
    instant_data_PREC = client.service.getData(duration='DAILY', stationTriplets=user_stationTriplets,
                                          elementCd='PREC', ordinal=1, beginDate=user_beginDate,
                                          endDate=user_endDate, getFlags = True)

    # convert the XML output to Python dictionary
    instant_dict_WTEQ = helpers.serialize_object(instant_data_WTEQ[0]['values'])
    instant_dict_TAVG = helpers.serialize_object(instant_data_TAVG[0]['values'])
    instant_dict_PREC = helpers.serialize_object(instant_data_PREC[0]['values'])

    # convert to Pandas DataFrame
    instant_df = pd.DataFrame.from_dict(instant_dict_WTEQ)
    instant_df['1'] = pd.Series(instant_dict_TAVG)
    instant_df['2'] = pd.Series(instant_dict_PREC)

    # rename columns
    instant_df.columns = ['SWE [in]', 'AirT [F]', 'PRCP [in]']

    # make type floats - this also changes 'None' to 'NaN'
    instant_df = instant_df.astype(float)

    # replace NaN values with interpolated values using pd.interpolate
    # linear interpolation is best
    # axis = 0 is needed so that this works over all columns
    instant_df = instant_df.interpolate(method='linear', axis=0)

    # return the dataframe
    return instant_df

3. Snow Water Equivalent¶

But what exactly is SWE? As the name suggests, snow water equivalent is the amount of water a snowpack contains, or the depth of water that would result from the complete melting of the snow in place. As we did with soil moisture, we can consider a representative portion of a snowpack of surface area $A$ and volume $V_{snow}$, where $$ V_{snow} = V_{ice} + V_{water} + V_{air} = h_s \cdot A $$ where $h_s$ is the height of the snowpack (see figure below). If we say the density of water and ice (at 0$^{\circ}$ C) are $\rho_{ice} = 917\text{ kg m}^{-3}$ and $\rho_{water} = 1000\text{ kg m}^{-3}$ respectively, then the snow-water equivalent can be computed via $$ h_{swe}=\frac{V_{water} + V_{ice}(\rho_{ice}/\rho_{water})}{A} = \frac{\rho_{snow}}{\rho_{water}}\cdot h_s $$

_Figure 2: Dimensions of a representative portion of a snowpack used in defining snowpack properties. $A$ is the area of the upper surface, and $h_s$ is the snow depth (Source: Dingman V3)_

4.2 Model Tuning and Training¶

Now it's time to train the model. Everything here is built for a 1D CNN model, which is found in the class torch.nn.Conv1D (if you are interested, see here) First, we will have to define some hyperparameters for how we want this model to run. The important ones we will be looking at are:

  • n_batch: the batch size of the model, which defines the number of samples to work through before updating internal model weights (think of this as how much you study before a quick quiz) - we set this to 15, each year being one batch of data
  • n_epoch: the number of epochs, which defines the number of times that the learning algorithm will work through the entire training dataset (think of this as how many times you go through all the material before a final exam)
  • learning_rate: the learning rate, which dictates how much to change the model in response to the estimated error each time the model weights are updated (how quickly you remember something you got wrong on a practice quiz). This is one of the most important hyperparameters to tune, because too large a learning rate may result in a model converging too quickly on a suboptimal result and too small a learning rate may result in a long training process that could get stuck.
  • nchannel: this is the number of input channels used in the first layer of the CNN, which is how many features (aka predictors) are being given to the model (in this case, 2: precipitation and temperature)

In general, lower learning rates require higher epochs, since a model with a low learning rate won't change much after one epoch. When experimenting with this code, you'll likely only want to tune n_epoch and learning_rate.

Other parameters are included below, including CPU/GPU capabilities (model.to(DEVICE)) and whether or not everything is printed from the model (model.verbose). Loss functions and optimizers are also used, which are an advanced feature of CNNs.

In brief, loss functions are used to gauge the error between the prediction and the target, while optimizers are algorithms that update the model weights after each epoch, based on the losses. (Here, we use the SmoothL1Loss and the ADAM optimizer).

Transformations are also done to normalize the variables (i.e., rescale the variables to a standard interval).

def cnn_flow(n_batch, N, n_epoch, n_batch_test, learning_rate, train_data, test_data):

    n_batch = n_batch # number of sets
    N = N # length of a set
    nchannel = 2 # temp and precip
    n_epoch = n_epoch
    learning_rate = learning_rate
    time = np.arange(N)

    # Choose the ML and associated options, models are stored in ML_models.py
    # and need to be imported up top if used
    model = RMM_NN(grid_size=[N],
                   channels=nchannel)
    model.to(DEVICE)

    model.verbose=False
    model.use_dropout = True


    # loss function
    loss_fn = torch.nn.SmoothL1Loss()

    # optimizer and solver, Adam works the best, regular SGD seems to work the poorest
    optimizer = torch.optim.Adam(model.parameters(), lr=learning_rate)


    # Setup transforms to get variables scaled from 0-1 or -1 to 1
    # first get maxima for flow and PRCP
    flow_max = np.max(train_data['flow'])
    precip_max = np.max(train_data['precip'])

    # set up transforms
    Temp_TRANSF = float32_clamp_scaling(src_range=[np.min(train_data['temp']), np.max(train_data['temp']) ], dst_range=[-1, 1])
    Flow_TRANSF = float32_clamp_scaling(src_range=[0, flow_max], dst_range=[0, 1])
    Precip_TRANSF = float32_clamp_scaling(src_range=[0, precip_max], dst_range=[0, 1])
    # INV_FLOW will be used to get usable model output
    INV_FLOW_TRANSF = float32_clamp_scaling(src_range=[0, 1], dst_range=[0, flow_max])



    #setup the input and ouput arrays
    input_temp = np.zeros((n_batch, nchannel, N))
    output_temp_temp = np.zeros((N))
    output_temp = np.zeros((n_batch, N))
    model_output = np.zeros(N)
    # ___
    # load all the transient variables for timesteps, ie the batch members and normalize


    P_temp = Precip_TRANSF(np.asarray(train_data['precip']))
    T_temp = Temp_TRANSF(np.asarray(train_data['temp']))
    flow_temp = Flow_TRANSF(np.asarray(train_data['flow']))

    for ii in range(0, n_batch):
        i_from = ii*N  #this should be a broadcast instead of a loop
        i_to = i_from + N
        input_temp[ii, 0, :] = P_temp[i_from:i_to]
        input_temp[ii, 1, :] = T_temp[i_from:i_to]
        output_temp[ii,:] = flow_temp[i_from:i_to]



    # convert the inputs and outputs (labels) from the temp NumPy vectors to Torch format
    # convert them to Floats
    torch_input = torch.from_numpy(input_temp)
    torch_label = torch.from_numpy(output_temp)
    torch_input = torch_input.type(torch.FloatTensor).to(DEVICE)
    torch_label = torch_label.type(torch.FloatTensor).to(DEVICE)
    # ___
    # Train the model

    for epoch in range(n_epoch):
        optimizer.zero_grad()
        # Forward pass
        batch_prediction = model(torch_input)
        loss = loss_fn(batch_prediction, torch_label)


        # Backward and optimize
        loss.backward()
        optimizer.step()


    torch.save(model, "flow_test.pt")


    # freeze the model
    model.use_dropout = False
    for parameter in model.parameters():
        parameter.requires_grad = False


    # time varying test datasets
    P_temp = Precip_TRANSF(np.asarray(test_data['precip']))
    T_temp = Temp_TRANSF(np.asarray(test_data['temp']))
    # time varying test datasets
    # we now need to predict one year at a time so this should duplicate what's above
    input_temp = np.zeros((n_batch_test, nchannel, N))
    for ii in range(0, n_batch_test):
        i_from = ii*N  #this should be a broadcast instead of a loop
        i_to = i_from + N
        input_temp[ii, 0, :] = P_temp[i_from:i_to]
        input_temp[ii, 1, :] = T_temp[i_from:i_to]
    # make a prediction setting n_batch = 0 to appropriately use the test_data
    input_temp[0, 0, :] = Precip_TRANSF(np.asarray(test_data['precip'][0:N]))
    input_temp[0, 1, :] = Temp_TRANSF(np.asarray(test_data['temp'][0:N]))

    predict_input = torch.from_numpy(input_temp)

    predict_input = predict_input.type(torch.FloatTensor).to(DEVICE)
    prediction = model(predict_input)
    #print(np.shape(prediction))
    model_output = INV_FLOW_TRANSF(prediction.data.cpu().numpy())
    #print(np.shape(model_output))
    # reshape the five years of prediction to one long year
    model_plot = np.reshape(model_output,(N*n_batch_test))

    return model_plot
